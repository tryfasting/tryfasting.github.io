# Instructions (for LLM coding agent) - Batch-generate multiple design variants for comparison

The v1.3 fix resolved the CSS specificity leaks correctly, but the overall page still doesn't evoke the feel of the original Swissfolio reference. Instead of iterating one change at a time with manual approval at each step, generate three parallel variants in a single pass, each on its own git branch, so they can all be reviewed together at the end.

## 1. Ground every variant in real measured values from the reference clone

The `swissfolio-reference` repo has now been added to this workspace. Before writing any variant, extract actual values from it (do not guess):

1. Open the reference project's rendered demo (or its source files: layout, components, tailwind config, global CSS) and record the real computed values for: hero heading font-size/line-height/letter-spacing at 1440px and 375px, spacing between major sections, the container's horizontal padding, and any typographic rhythm patterns (e.g. manual line breaks, paragraph width).
2. Produce a short table: `current project value` vs `reference value` for each of these properties, and save it as `policy/reference-diff.md`. This table is the factual basis for all three variants below — do not invent numbers that aren't grounded in this table.

## 2. Create three variants on separate git branches, all based on current `main` (v1.3)

For each variant, branch from the current v1.3 commit, apply the described changes, commit, and tag. Do not wait for approval between variants — complete all three, then report all three together.

**Branch `variant-a-subtle`**
Small, conservative move toward the reference values: increase spacing between major sections by roughly 20-30% over current policy tokens, keep h1 size as-is, keep index-number as-is. This variant tests whether spacing alone (without touching type scale) can recover more of the reference's airy feel.

**Branch `variant-b-scale`**
Push the typographic scale contrast closer to the reference measured values: increase h1 clamp max further toward the reference's actual heading size, increase index-number weight/size proportionally, keep spacing at current v1.3 policy values. This variant isolates the effect of scale contrast alone.

**Branch `variant-c-combined`**
Apply both the spacing increase from variant-a and the scale increase from variant-b together, plus one additional structural change: make the hero's status/principles two-column block visually denser (reduce the gap between the two columns, align their baseline with the section above more tightly). This variant tests the combined effect.

All three variants must still respect existing constraints in `policy/design-tokens.md`: light mode only, accent color usage capped at ~3% of viewport, no large solid-color blocks, Pretendard-only font stack, no Tailwind size utilities applied directly on components (per the rule added in v1.3).

## 3. Capture and organize results for batch review

For each of the three branches:
1. Take screenshots at 1440px and 375px viewports, saved as `artifacts/{branch-name}_preview-1440.png` and `artifacts/{branch-name}_preview-375.png`.
2. Commit with message `experiment({branch-name}): <one-line summary of what changed>` and tag as `exp-{branch-name}`.
3. Do not merge any of these branches into `main`. They are exploration branches only.

## 4. Produce a single comparison report

After all three branches are done, switch back to `main` and create `artifacts/variant-comparison.md` containing:
- The reference-diff table from step 1.
- For each variant: what was changed, the exact CSS/token values used, and the screenshot file paths.
- A short factual note (no aesthetic judgment) on which variant moved closest to the reference's measured spacing/scale values, and which moved furthest.

Do not pick a "winner" or merge anything. Present all three variants with their screenshots and the comparison report in one final response so they can be reviewed together instead of one at a time.
